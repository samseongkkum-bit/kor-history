# 한옥 마당 한국사 퀴즈 (여러 명 동시 접속)

초·중학생 체험 부스에서 쓰는 한국사 퀴즈 게임입니다.
학생들이 **각자 자기 폰·태블릿으로 같은 한옥 마당에 들어와**, 자기 캐릭터를 움직여
정답 자리(돗자리)에 서면 함께 채점받습니다.

| 화면 | 주소 | 어디에 띄우나 |
|---|---|---|
| **진행자 화면** | `/host` | 부스의 큰 모니터·노트북 |
| **학생 화면** | `/play` | 학생들의 폰·태블릿 |
| **혼자 하기** | `/solo` | 비상용 1인 버전(인터넷 없이도 됨) |

---

## 처음 설정 (한 번만)

인터넷에 올려서 쓰는 방식이라, **Supabase**(자료를 보관하고 실시간으로 나르는 곳)와
**Vercel**(화면을 보여 주는 곳) 두 군데에 가입해야 합니다. 둘 다 무료 플랜으로 충분합니다.

### 1단계. 준비물 확인

컴퓨터에 **Node.js 20 이상**이 필요합니다. 터미널(맥은 *터미널*, 윈도우는 *PowerShell*)에서:

```bash
node -v
```

`v20.0.0`처럼 나오면 됩니다. 안 나오면 <https://nodejs.org> 에서 **LTS** 버전을 설치한 뒤 터미널을 새로 여세요.

그다음 이 폴더에서 한 번만:

```bash
npm install
```

### 2단계. Supabase 프로젝트 만들기

1. <https://supabase.com> → **Start your project** → 가입
2. **New project**
   - **Name**: `hanguksa-quiz` (아무거나)
   - **Database Password**: 아무 비밀번호나 정하고 **꼭 따로 적어 두세요.** 나중에 다시 못 봅니다.
   - **Region**: **Northeast Asia (Seoul)** — 가까울수록 캐릭터가 덜 끊깁니다
   - **Plan**: Free
3. 2분쯤 기다리면 준비됩니다.

### 3단계. 열쇠 두 개를 적어 두기

Supabase 대시보드 **Project Settings(톱니바퀴) → API** 에서 두 가지를 복사합니다.

**`supabase/public-config.json`** 을 열어 두 줄을 바꾸세요.

```json
{
  "supabaseUrl": "https://여기에_Project_URL",
  "supabaseAnonKey": "여기에_anon_public_키"
}
```

이 파일은 저장소에 함께 올라갑니다. **그래도 괜찮습니다** — `anon` 키는 원래
브라우저에 담아 쓰라고 만든 공개 열쇠이고, 표에 손대는 것은 4단계에서 거는
잠금 규칙(RLS)이 막습니다. 덕분에 **Vercel에 환경 변수를 따로 넣지 않아도 됩니다.**

> 키를 저장소에 두기 싫으면 `.env.local` 파일에 `SUPABASE_URL=` / `SUPABASE_ANON_KEY=` 로
> 적어 두거나 Vercel 환경 변수에 넣어도 됩니다. 그쪽이 있으면 그 값이 우선합니다.

> **`service_role` 키는 절대 쓰지 마세요.** 그 키는 모든 잠금을 풀어 버립니다.
> 화면에 들어가는 건 `anon` 키뿐이고, 이건 원래 공개되는 열쇠입니다
> (표에 손대는 건 아래 4단계에서 거는 잠금 규칙이 막습니다).
>
> `.env.local` 은 git에 올라가지 않게 해 두었습니다.

### 4단계. 표와 함수 올리기

1. Supabase 대시보드 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 폴더의 **`supabase/all.sql`** 파일을 열어 **전체 복사** → 붙여넣기 → **Run**
   - 터미널에서 `open supabase/all.sql` 하면 바로 열립니다.
3. **Success** 가 뜨면 끝입니다. (여러 번 실행해도 괜찮습니다)

제대로 올라갔는지 확인:

```bash
npm run db:check
```

`모두 정상이에요` 가 나오면 됩니다.

> 이 단계까지 하고 나면 `participation` 표에 점검용 기록이 한두 줄 남아 있을 수 있습니다.
> 부스 전에 `supabase/reset-participation.sql` 로 비우고 시작하세요(아래 "참여 인원 기록" 참고).

### 5단계. Vercel에 올리기

1. 이 폴더를 GitHub 저장소로 올립니다.
2. <https://vercel.com> 가입 → **Add New… → Project** → 그 저장소 선택
3. **Deploy** (3단계를 했다면 환경 변수는 넣지 않아도 됩니다). 1분쯤 뒤 `https://○○○.vercel.app` 주소가 나옵니다.

끝입니다. 이제 아래 주소를 씁니다.

- 진행자: `https://○○○.vercel.app/host`
- 학생: `https://○○○.vercel.app/play`

> 그 뒤로는 GitHub에 push 할 때마다 Vercel이 알아서 다시 배포합니다.
> 환경 변수를 쓰는 쪽을 골랐다면, 변수를 고친 뒤 Vercel에서 **Redeploy** 를 한 번 눌러야 반영됩니다.

## 부스에서 쓰는 법

### 1. 진행자 화면 열기

1. 노트북 브라우저에서 **`https://○○○.vercel.app/host`** 를 엽니다.
2. **[방 만들기]** 를 누릅니다.
3. **4자리 입장 코드**와 **QR 코드**가 크게 나옵니다. 이 화면을 학생들에게 보여 주세요.

화면 구성
- 왼쪽: 한옥 마당 (학생 캐릭터들이 돌아다닙니다)
- 오른쪽: 입장 코드·QR / 시작·다음 문제·강제 종료 / 지금 순위 / 학생 명단
- 오른쪽 맨 위: **오늘 참여 인원 합계**

> 게임이 시작되면 QR이 작게 접힙니다. 늦게 온 학생이 있으면 **코드 칸을 한 번 누르면** 다시 커집니다.

### 2. 학생 입장

- **QR 코드 찍기** — 폰 카메라로 찍으면 코드까지 자동으로 들어갑니다 (가장 쉽습니다)
- **주소 치기** — `https://○○○.vercel.app/play` 에 들어가 4자리 코드를 넣습니다

학생 화면에서 할 일: **입장 코드 → 이름(최대 8자) → 저고리 색 → [마당에 들어가기]**

> **개인정보는 받지 않습니다.** 이름 칸에 **별명을 써도 된다고 안내해 주세요.**
> 서버에 남는 기록에는 이름이 들어가지 않고 인원 수와 점수만 남습니다.
>
> 같은 방에 같은 이름이 있으면 자동으로 숫자가 붙습니다(`민수`, `민수2`).
> 장난스러운 이름은 진행자 화면 명단의 **[내보내기]** 로 내보낼 수 있습니다.

**한 방에 최대 30명**입니다. 더 많으면 방을 하나 더 만들어 나눠 받으세요(여러 방을 동시에 열 수 있습니다).

### 3. 게임 진행

1. 학생들이 다 들어오면 **단계**를 고릅니다.
   - **초등부** — O/X 30문제 중 10문제
   - **중등부** — 객관식 15 + O/X 15, 총 30문제 중 10문제
2. **[게임 시작]**
3. 문제가 나오면 학생들이 캐릭터를 움직여 정답 자리에 섭니다.
   - **제한 시간**: O/X 12초, 객관식 20초
   - 시간이 끝나면 **그때 서 있던 자리**로 채점합니다.
   - 미리 정하려면 **[여기로 결정!]** 을 누릅니다. 빨리 정할수록 동점일 때 순위가 앞섭니다.
4. 시간이 끝나면 **정답 공개 → 해설 → 그때까지의 순위(상위 5명)**
5. **[다음 문제]** 를 눌러 넘어갑니다. 설명할 시간을 충분히 가지세요.
6. 10문제를 다 풀면 **최종 순위와 각자의 칭호**

### 학생 조작법

- 방향키 또는 **W A S D**
- **마당을 손가락으로 누르면** 그쪽으로 걸어갑니다 (폰·태블릿에서 가장 편합니다)
- 화면 아래 **방향 버튼** (태블릿용)
- 모르겠으면 마당 구석의 **두루마리**로 가거나 **[힌트 보기]**. **힌트는 그 학생에게만 보입니다.**

### 칭호 (10점 만점)

| 점수 | 칭호 | 점수 | 칭호 |
|---|---|---|---|
| 0–2점 | 천민 | 7–8점 | 귀족 |
| 3–4점 | 양민 | 9점 | 조선의 학자 |
| 5–6점 | 평민 | 10점 | 왕 |

### 이럴 때는 이렇게

| 상황 | 어떻게 되나요 |
|---|---|
| 학생이 새로고침했어요 | **같은 기기면 이름과 점수가 그대로 이어집니다.** 정해 둔 자리까지 기억합니다. |
| 와이파이가 잠깐 끊겼어요 | 다시 붙으면 저절로 이어집니다. |
| 진행자 화면을 새로고침했어요 | **방은 사라지지 않습니다.** 같은 방으로 다시 들어갑니다. |
| 진행자 화면이 멈췄어요 | 채점은 학생 화면이 대신 불러 줍니다. 결과는 똑같습니다. |
| 학생이 게임 중간에 들어왔어요 | **다음 문제부터** 함께 풉니다(지금 문제는 구경만). |
| 시간이 모자라요 | **[강제 종료]** 를 누르면 그때까지의 점수로 최종 순위가 나옵니다. |
| 한 판 더 하고 싶어요 | **[새 문제로 한 판 더]**. **30문제를 한 바퀴 다 돌 때까지 같은 문제가 다시 나오지 않습니다.** |
| 인터넷이 아예 안 돼요 | **`/solo`** 로 한 명씩 돌아가며 하면 됩니다(아래 참고). |

## 인터넷이 안 될 때 (비상용)

`/solo` 는 1인용이고 **한 번 열어 두면 인터넷 없이도 끝까지 됩니다.**
부스 가기 전에 노트북·태블릿에서 `/solo` 를 한 번 열어 두면, 현장에서 와이파이가
안 돼도 그 기기로 한 명씩 돌아가며 할 수 있습니다.

노트북에서 직접 띄우려면(인터넷 없이):

```bash
npm start
```

그러면 `http://localhost:3000/solo` 로 열 수 있습니다.
단, **여러 명 동시 접속은 Supabase가 필요하므로 인터넷 없이는 안 됩니다.**

## 참여 인원 기록 (부스 보고서용)

게임이 한 판 끝날 때마다 Supabase의 `participation` 표에 한 줄씩 쌓입니다.

| 항목 | 뜻 |
|---|---|
| `day` / `at` | 날짜와 시각 |
| `level_name` | 단계 (초등부 / 중등부) |
| `players` | 그 판에 참여한 인원 |
| `questions` | 그 판에서 푼 문제 수 |
| `avg_score` | 평균 점수 |

**학생 이름은 남지 않습니다.**

> **부스 당일 아침에 한 번 지우고 시작하세요.** 시험 삼아 돌려 본 기록이 섞여 있으면
> "오늘 참여 인원 합계"가 실제보다 크게 나옵니다.
> SQL Editor 에 `supabase/reset-participation.sql` 을 붙여넣고 Run 하면 비워집니다.

보는 방법: Supabase 대시보드 → **Table Editor** → `participation`.
엑셀로 받으려면 표 위의 **Export → CSV** 를 누르세요.
진행자 화면 오른쪽 위의 **"오늘 참여 인원 합계"** 숫자를 그대로 써도 됩니다.

## 문제 고치기

문제는 **`data/questions.json`** 한 파일에 들어 있습니다. 메모장이나 텍스트 편집기로 고치면 됩니다.

### 파일 생김새

```json
{
  "elem": {
    "name": "초등부",
    "kind": "O/X 퀴즈",
    "desc": "태극기, 한글, 명절처럼 생활 속에서 만나는 우리 역사",
    "questions": [
      {
        "t": "ox",
        "q": "우리나라 국기의 이름은 '태극기'이다.",
        "a": "O",
        "hint": "가운데에 빨간색과 파란색 동그라미가 있어요.",
        "ex": "태극기는 가운데 태극 무늬와 네 귀퉁이의 검은 막대(4괘)로 이루어져 있어요."
      }
    ]
  }
}
```

| 이름 | 뜻 |
|---|---|
| `t` | 문제 종류. `"ox"` 는 O/X, `"mc"` 는 객관식 |
| `q` | 문제 문장 |
| `a` | 정답. O/X는 `"O"` 또는 `"X"`, 객관식은 **몇 번째 보기인지 0부터 센 숫자** |
| `c` | 객관식일 때만. 보기 **4개** |
| `hint` | 힌트 한 줄 |
| `ex` | 해설 한 줄 |

### 객관식 예시

```json
{
  "t": "mc",
  "q": "우리 역사에서 처음 세워진 나라는?",
  "c": ["고구려", "고조선", "신라", "가야"],
  "a": 1,
  "hint": "단군 이야기와 관련 있어요.",
  "ex": "고조선은 단군왕검이 세운 우리 역사 최초의 국가예요."
}
```

> `"a": 1` 은 **두 번째** 보기인 `"고조선"` 이 정답이라는 뜻입니다.
> 0 = 첫 번째, 1 = 두 번째, 2 = 세 번째, 3 = 네 번째.
> 보기 순서는 게임마다 자동으로 섞이지만 정답은 따라다니므로 걱정하지 않아도 됩니다.

### 고친 뒤 반영하기

```bash
npm run seed
```

그러면 `supabase/all.sql` 이 새로 만들어집니다. **4단계처럼 SQL Editor에 붙여넣고 Run** 하세요.
`/solo` 화면에도 반영하려면 Vercel에 다시 올리면 됩니다(GitHub에 push하면 자동입니다).

### 주의할 점

- 큰따옴표 `"` 와 쉼표 `,` 를 빠뜨리지 마세요. 하나만 틀려도 올라가지 않습니다.
- 문제 안에 큰따옴표를 쓰려면 `\"` 처럼 앞에 `\` 를 붙입니다.
- **단계마다 30문제를 권합니다.** 한 판에 10문제씩 뽑으므로 30문제면 세 판 동안 겹치지 않습니다.
- 고치기 전에 파일을 복사해 두면 안전합니다.
- 올리고 나서 `npm run db:check` 로 확인하세요.

## 잘 안 될 때

| 증상 | 해결 |
|---|---|
| 화면에 "아직 준비가 안 됐어요" | `supabase/public-config.json` 이 비어 있습니다(3단계). 고친 뒤 GitHub에 push 하면 Vercel이 다시 배포합니다. |
| `npm run db:check` 에서 "함수를 찾을 수 없어요" | 4단계(`supabase/all.sql` 붙여넣기)를 안 했습니다. |
| 방을 만들어도 학생이 못 들어옴 | 학생이 **다른 주소**에 들어갔을 수 있습니다. QR을 찍게 하세요. |
| 캐릭터가 뚝뚝 끊겨 움직임 | 와이파이가 약합니다. 학생들이 공유기 가까이 모이면 나아집니다. |
| 한참 뒤 화면이 멈춘 느낌 | 진행자 화면을 새로고침하세요. 방과 점수는 그대로입니다. |
| 글꼴이 평소와 달라 보임 | 인터넷이 느려 구글 폰트를 못 받은 것입니다. 글자는 그대로 잘 읽힙니다. |
| 인터넷이 아예 안 됨 | `/solo` 로 한 명씩 하세요. |

## 개발자용 메모

```bash
npm start          # 로컬에서 화면 띄우기 (Supabase에 붙어서 동작)
npm run db:check   # Supabase에 표·함수가 제대로 올라갔는지
npm run db:push    # SUPABASE_DB_URL 이 있으면 바로 올리기(없으면 all.sql 안내)
npm run seed       # questions.json → supabase/all.sql 다시 만들기
npm test           # SQL 함수 테스트 (로컬 Postgres 에 임시 DB를 만들어 돌림)
npm run test:live  # 실제 Supabase 에 대고 한 판(10문제) 돌려 보기 (약 3분)
npm run test:e2e   # Playwright: 진행자 1명 + 학생 3명 한 판, 폰·태블릿 레이아웃
```

> `SUPABASE_DB_URL` 을 쓰려면 Supabase 대시보드 → **Connect → Session pooler** 의 URI 를 넣으세요.
> **Direct connection 주소(`db.*.supabase.co`)는 IPv6 전용**이라 IPv4만 되는 망에서는 연결되지 않습니다.

### 어디서 무엇을 정하나

- **채점과 시간은 Postgres 함수가 정합니다.** 화면은 `ends_at` 을 받아 남은 시간을 그릴 뿐입니다.
- `grade_question()` 은 **마감 시각 전에는 거부**하고, **두 번 불러도 결과가 같습니다.**
  그래서 진행자 화면이 부르고, 멈춰 있으면 학생 화면이 조금 늦게 대신 부릅니다.
- 정답·해설·힌트·열쇠는 **따로 떼어 둔 표**에 있고 손님(anon)은 읽을 수 없습니다.
  문제를 내려보낼 때 마감 전까지 정답을 빼고, 힌트는 본인 RPC 로만 나갑니다.
- 위치는 표에 싣지 않고 **Realtime Broadcast** 로만 주고받습니다.
  학생들이 각자 보내면 메시지가 사람 수의 제곱으로 늘어나므로,
  **진행자 화면이 모아서 초당 2번 한꺼번에 되뿌립니다.**
  (진행자 화면이 닫혀 있으면 서로의 캐릭터만 안 보일 뿐, 게임과 채점은 그대로 됩니다.)
- 점수는 **정답 1점**뿐입니다(칭호는 이 10점 만점 기준). **빠르기 보너스**는 순위 동점 처리에만 씁니다.
- 방은 아무도 없으면 **15분 뒤** 정리됩니다.

### 무료 플랜에서 신경 쓸 것

Supabase 무료 플랜의 Realtime 메시지는 월 200만 건입니다.
위와 같이 모아서 뿌리기 때문에 30명 기준으로 **초당 90건 남짓**이고,
실제 부스에서는 **10시간 넘게** 쓸 수 있습니다. 한 부스 행사에는 넉넉합니다.
